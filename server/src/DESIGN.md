# 关键设计说明

## 1. 统一任务实体（单一事实源）
- `tasks` 只有一个。正文 todo 块的 `task_id`、`decision_task_refs.task_id`、汇总表行都引用它。
- 因此「正文里的待办」和「汇总表里的待办」不可能不一致；同一任务被正文多次提及、被多个决议引用，
  通过 `referenceReport` 显式可见（验收：同任务多处引用）。
- 块只是**呈现/编排**，删除块不触碰任务。任务取消必须是显式业务动作。

## 2. 编辑即建 与 定稿一次生成 —— 同一实体的生命周期
- 草稿期 upsert 即落 `provisional`：页面立刻能分派负责人、被决议引用、进汇总表（所见即所得）。
- 定稿在一个事务里把仍为 provisional 的任务批量转 established（UPDATE...WHERE status='provisional' 天然幂等），
  随后写 finalize 版本与快照、翻会议状态。崩溃后用同一 idempotency_key 重放：
  已转换的不会重复转换，`finalize_keys` 命中则直接返回既有快照。
- 这避免了「草稿待办」和「正式待办」两套表的同步难题，也满足幂等关联。

## 3. 负责人沿革与签收隔离
- `task_assignments` 只追加不改写；当前负责人 = `superseded_at IS NULL` 的最新行。
- `task_acknowledgements` 外键到**具体 assignment**。负责人一变，旧 assignment 被取代，
  任务视图的 `acknowledged` 立即变 false；旧签收行仍保留在沿革里（可审计），但绝不代表对新分派的确认。
- 负责人允许为空（`assignee NULL`，对应 change_type=clear），缺失被定稿校验与页面徽标显式暴露，而非隐式阻止录入。

## 4. 截止时点
- 仅日期：存日历日，解释锚点是会议时区。它没有「时刻」，因此也没有 UTC，跨时区协作者看到的是同一天。
- 具体时刻：录入墙上时间 + IANA 时区，服务端用 Intl 偏移两次校正（处理 DST 跳空/回退）得 UTC 存储；
  展示用原时区还原并附 UTC，避免「18:00 是谁的 18:00」歧义。

## 5. 离线并行
- 每次编辑提交 `(base_rev, ops)`。服务端取 base/head/客户端变更做三路合并：
  仅一方改动→采纳；双方改不同字段→字段级合并；同字段分叉 / 改删冲突→409 并给出三方取值。
- 页面冲突面板支持「拉取最新版本并变基重放」。

## 6. 快照、撤回与导出
- 定稿快照自包含且不可变。定稿后撤回决议 → 新增 `amendment` 快照（原 final 快照保留），
  导出可选 seq 还原任意历史版本。
- 导出/正式渲染**只读快照**：事后改负责人、完成任务都不会回改历史文件（验收点）。

## 7. 渲染断点续跑
- 五阶段顺序管线，每阶段完成即把确定性片段写入 `render_jobs.checkpoints_json` 并推进 `stage_seq`。
- 中断（崩溃/注入故障）后用同一 client_token 重跑：从 stage_seq 续算，前序片段复用；完成后再跑直接返回结果。
